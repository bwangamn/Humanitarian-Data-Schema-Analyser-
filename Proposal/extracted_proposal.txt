1. Introduction
Humanitarian organisations operate in data-intensive environments where accurate, well-structured, and interoperable data is critical for decision-making, coordination, and resource allocation .These organisations collect and manage data using a wide range of tools and formats, including XLSForm (used in ODK and KoBoToolbox), XML-based standards such as XForms and IATI ,HXL-tagged CSV files, and custom JSON or CSV exports from operational systems. While these formats enable flexibility, they introduce significant challenges in data integration and analysis due to inconsistencies in structure, naming conventions, and data types (Rahm & Bernstein, 2001).
Before any advanced data operations such as Federated Learning or cross-organisational analytics can be performed, it is necessary to understand and standardise the structure of datasets. Currently, this process is largely manual, requiring data engineers to inspect schemas, identify relationships, infer types, and document inconsistencies. This approach is time-consuming, error-prone, and does not scale effectively when working with multiple organisations and large datasets (Do & Rahm,2000).
The Humanitarian Data Schema Analyzer project proposes the development of a Python-based tool that automates the analysis and profiling of diverse data schemas (Abedjan, 2019; Alrehamy & Walker, 2018). The system will parse multiple humanitarian data formats, extract structural metadata, perform data profiling, and generate standardised outputs such as JSON Schema and human-readable reports. By automating schema understanding, the tool will reduce manual effort, improve data quality, and enable interoperability across systems.
1.1Problem Statement
Humanitarian organisations face significant challenges in analysing and integrating data due to the diversity of formats and lack of standardisation. Data collected through platforms such as ODK, KoBoToolbox, and IATI often differs in structure, hierarchy, and semantics, making it difficult to combine datasets or perform unified analysis.
Currently, schema analysis is performed manually, requiring technical expertise and considerable time. This leads to several issues. First, the process does not scale when dealing with multiple organisations or large datasets. Second, manual analysis introduces inconsistencies and errors in schema interpretation. Third, the lack of automated tools delays downstream processes such as data integration, validation, and machine learning.
Additionally, without proper profiling, data quality issues such as missing values, inconsistent types, and anomalies often go undetected until later stages, increasing the cost of correction. There is therefore a need for an automated system that can analyse, profile, and standardise schemas across multiple humanitarian data formats efficiently and reliably.
1.2Project Aim

2. Literature Overview
2.1 Data Heterogeneity in Humanitarian Systems
Humanitarian data ecosystems are characterised by significant heterogeneity due to the wide range of tools and standards used for data collection and reporting. Platforms such as Open Data Kit (ODK), KoboToolbox, the International Aid Transparency Initiative (IATI), and the Humanitarian Data Exchange (HDX) generate data in formats including XLSForm, XML, JSON, and CSV, each with distinct structural and semantic properties. This diversity creates challenges in data integration, interoperability, and analysis across organisations. As noted by Keßler and Hendrix (2015), humanitarian organisations frequently exchange data using incompatible structures and semantics, motivating the development of common standards such as the Humanitarian Exchange Language (HXL) to improve interoperability.
HXL provides a lightweight semantic tagging standard that enables datasets from different humanitarian actors to be consistently described without requiring major changes to existing data collection processes (Keßler & Hendrix, 2015). Similarly, the International Aid Transparency Initiative (IATI) defines a standardised XML structure, schemas, codelists, and rulesets for publishing development and humanitarian activity information (International Aid Transparency Initiative [IATI], 2018). Within the ODK ecosystem, the ODK XForms Specification provides a common XML-based form description standard defining elements such as data instances, bindings, data types, and form controls (Open Data Kit, 2019). These standards provide greater consistency while still introducing different structural and semantic requirements that must be understood when integrating data from multiple humanitarian systems.
Rahm and Bernstein (2001) identify schema heterogeneity as one of the primary barriers to effective data integration, noting that differences in structure, naming conventions, and data representation require complex mapping and transformation processes. In humanitarian contexts, these challenges are amplified by the coexistence of multiple standards and independently developed data collection tools. Consequently, understanding and harmonising schemas becomes a prerequisite for collaborative data analysis and effective humanitarian information management.
2.2 Schema Matching and Data Integration
Schema matching is a fundamental process in data integration, involving the identification of correspondences between elements of different data schemas. According to Rahm and Bernstein (2001), schema matching techniques range from manual approaches to semi-automated and fully automated methods that leverage structural, syntactic, and semantic similarities.
Do and Rahm (2000) further highlight that manual schema analysis is time-consuming and prone to inconsistencies, particularly when dealing with large and complex datasets. Recent approaches, such as those proposed by Amghar et al. (2023), emphasise automated schema integration techniques that reduce human intervention and improve scalability in big data environments. These studies underscore the importance of developing automated tools capable of analysing and standardising schemas, which directly aligns with the objectives of the Humanitarian Data Schema Analyzer.
2.3 Data Profiling and Data Quality Assessment
Data profiling is a critical step in understanding the structure, content, and quality of datasets. It involves analysing data to generate statistics, detect anomalies, and infer data types. Abedjan (2019) defines data profiling as a foundational process in data engineering that enables better decision-making by providing insights into data characteristics.
In the context of humanitarian data, profiling is particularly important due to frequent issues such as missing values, inconsistent formats, and data entry errors. Automated profiling tools can identify these issues early in the data pipeline, reducing the cost and effort required for data cleaning and improving overall data quality. The integration of data profiling capabilities into schema analysis tools enhances their usefulness by not only describing structure but also evaluating the reliability of the data itself.
2.4 JSON Schema and Data Standardisation
JSON Schema has emerged as a widely adopted standard for defining and validating the structure of JSON data. It provides a formal specification for describing data types, constraints, and relationships, enabling automated validation and interoperability between systems.
Attouche et al. (2023) highlight the importance of JSON Schema in modern data systems, particularly in ensuring consistency and correctness in data exchange. Similarly, Habib et al. (2019) emphasise its role in enforcing type safety and enabling automated validation processes. By generating JSON Schema outputs, the proposed system will provide a standardised representation of heterogeneous data formats, facilitating integration and validation across different platforms
2.5 Automated Data Integration Tools
Recent advancements in data engineering have led to the development of tools that automate schema analysis and data integration. Alrehamy and Walker (2018) introduced SemLinker, a system designed to automate data integration processes for non-expert users, demonstrating the potential of intelligent tools in simplifying complex data workflows.
More recent research by Flores et al. (2025) explores techniques for enhancing data discovery through contextual filtering, further improving the efficiency of data integration systems. These approaches highlight the growing importance of automation in handling large-scale, heterogeneous datasets. The Humanitarian Data Schema Analyzer builds on these concepts by focusing specifically on schema understanding and profiling as a foundational step in automated data integration.
2.6 Machine Learning Approaches to Schema Matching 
Emerging research has explored the use of machine learning techniques to improve schema matching accuracy. Koutras et al. (2020) introduced the Valentine framework, which evaluates multiple schema matching techniques to improve dataset discovery. Similarly, Shraga and Gal (2021) proposed a deep learning-based approach that incorporates data quality awareness into schema matching processes.
While the current project does not implement machine learning, these studies provide insight into future directions and highlight the potential for extending the proposed system with intelligent matching capabilities.

3.2Ethical and Legal Considerations
Data privacy & Minimal Exposure: The tool will exclusively process publicly available, synthetic, or rigorously anonymised datasets. To ensure the safety of vulnerable populations represented in humanitarian data, the system will not attempt to re-identify anonymised records and will actively discard any inadvertent Personally Identifiable Information (PII) it encounters during the parsing phase.
User consent & Data Minimization: The architecture is designed to process schema and metadata rather than retaining the underlying raw data. By ensuring no sensitive personal data is stored, cached, or persistently processed, the project mitigates the risk of unauthorized access to consent-bound information.
Security & Data Protection Frameworks: The tool's operational workflows will adhere to established data protection principles (such as GDPR and the UN Development Group's data privacy guidelines). Even when processing local files, memory management protocols will ensure that temporary data buffers are securely cleared after the schema analysis and profiling steps are complete.
Intellectual Property & Accessibility: To maximize impact within the resource-constrained humanitarian sector, the tool will be released under a permissive open-source license (such as MIT or Apache 2.0). This ensures clear intellectual property boundaries, allows NGOs to freely integrate the tool into their proprietary systems, and encourages collaborative contributions from the global open-source community.

3.4 System Diagrams
This section presents the visual representations of the system architecture, data flow, and internal component structure of the Humanitarian Data Schema Analyzer. These diagrams provide a clear understanding of how data is processed, how system components interact, and how outputs are generated.


Figure 1: System Architecture Diagram
The system architecture diagram illustrates the overall structure of the proposed tool. Input datasets in various formats, including CSV, JSON, XML, XLSForm are first processed by specialised format parsers. These parsers extract structural metadata, which is then transformed into a unified schema representation. The profiling engine operates on this standardised schema to perform statistical analysis, type inference, and anomaly detection. Finally, the processed data is passed to the output generator, which produces JSON Schema files and human-readable HTML reports. The entire system is controlled through a command-line interface (CLI), enabling efficient user interaction and integration into automated workflows.




Figure 2: Data Flow Diagram (DFD)
The data flow diagram illustrates how data moves through the system from input to output. The process begins with the user providing dataset files as input. These datasets are passed through the parsing stage, where their structure is analysed and schema information is extracted. The extracted schema is then processed by the profiling module, which generates statistical summaries and identifies potential data quality issues. The final stage involves generating outputs in the form of JSON Schema documents and HTML reports. This diagram highlights the sequential transformation of data and the key processing stages within the system.



Figure 3: Component Diagram
The component diagram provides a detailed view of the internal structure of the system and the interaction between its modules. The CLI module serves as the entry point, receiving user commands and passing them to the controller or orchestrator. The controller coordinates the execution of different parser modules, including CSV, JSON, XML, and XLSForm parsers. These parsers extract schema information and pass it to the unified schema representation module, which standardises the data structure. The profiling module then analyses the standardised schema using statistical techniques. Finally, the output generator produces JSON Schema files and HTML reports. This modular design ensures scalability, maintainability, and ease of extension.

4. Expected Outcomes
The project will deliver a comprehensive suite of utilities designed to streamline humanitarian data operations. The specific deliverables include:
A Functional Python-Based Schema Analysis Tool: The core deliverable is a robust, modular Python application. It will be built using modern, maintainable coding standards, ensuring it is lightweight, highly performant, and easily extensible by future developers.
Specialized Humanitarian Data Parsers: A collection of ingestion modules tailored for formats frequently encountered in crisis response and development sectors. This includes standard formats (CSV, JSON, Excel, XML) as well as specific humanitarian exports (e.g., KoboToolbox data, HXL-tagged datasets, and IATI standard files).
Advanced Data Profiling Engine: An analytical component that goes beyond basic type-checking. It will perform statistical profiling to infer data types, calculate distributions, and detect anomalies such as outliers, inconsistent formatting, or missing values that frequently plague field-collected data.
Unified Schema Representation Model: An internal, standardized data structure that maps diverse, chaotic input datasets into a single, normalized format. This allows the profiling engine to treat all data uniformly, regardless of its original source format.
Multi-Format Report Generation: * JSON Schema: For machine-to-machine integration, allowing the tool's output to be consumed by other automated data pipelines or validation tools.
HTML Reports: Interactive, human-readable dashboards that provide data officers with visual summaries of data health, schema structures, and identified anomalies.
Command-Line Interface (CLI): A fully featured CLI equipped with customizable arguments and flags. This ensures the tool can be run manually by data scientists or seamlessly embedded into automated CI/CD pipelines, cron jobs, and data ingestion workflows.
Comprehensive Documentation: A complete knowledge base, including a quick-start guide, detailed API documentation, architectural overviews, and a final project report detailing the methodology, challenges overcome, and the tool's impact on humanitarian data readiness.
